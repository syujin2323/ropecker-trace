# 실험 (14주차) — 계획

13주차 활동 6에 따라 14주차 실험의 **변수·지표·반복 횟수·측정 조건**을 미리 정합니다(13주차 자료 10쪽).
원논문 수치와 직접 비교하지 않고, **같은 조건에서 변수 하나만 바꾼 결과**를 비교합니다.

> 상태: 초안(송유진, 11/24). 팀 검토 뒤 11/29에 확정하고, 입력 목록은 13주차 추가 사례 결과(`results/w13/`)를 보고 확정합니다.

## 실험 1 (주 실험): 임계값 T

| 항목 | 내용 |
|---|---|
| 변수 | T = 5, 6, …, 17 (13개). 11주차 보고서 4.3-5의 계획이고, 논문 Ⅶ-A의 권장 범위 11~16을 포함한다 |
| 고정 | W = 8192, 판정 연쇄 ≥ T(11주차 기준), LBR 깊이 16, 정렬 검사 끔 |
| 입력 | 정상: 합성·실제 `f1-normal`, 13주차 추가 정상 입력(E12). 위반: 합성·실제 `f2-violation`, 경계 11·10(합성과 실제 E1), 13주차 추가 위반 입력 |
| 지표 | 정상 오탐 수(정상 트레이스 중 ROP 판정), 위반 탐지 수와 탐지 스텝이 execve 스텝보다 앞인지, 판정 연쇄 길이, 정상 트레이스의 최대 연쇄 |
| 반복 | 판정·연쇄·스텝은 같은 입력이면 항상 같다(결정적). 조건마다 3회 실행해 같은지 확인하고 그 값을 대표값으로 한다. 분석 시간은 참고로 5회 중앙값 |

**실행 전 가설:**
- 실제 정상 트레이스의 최대 연쇄가 1이므로 T ≥ 2부터 오탐이 없다.
- 실제 위반(연쇄 18)은 T ≤ 18에서 탐지된다.
- 과거 연쇄는 LBR 16개가 상한이라, T ≥ 17에서는 미래 연쇄 없이는 탐지할 수 없다.

## 실험 2 (보조): 윈도 크기 W

| 항목 | 내용 |
|---|---|
| 변수 | W = 4096, 8192, 16384, 20480 (논문 Ⅶ-C: 8KB·16KB로 실험, 20KB 미만 권장) |
| 고정 | T = 11, 판정 연쇄 ≥ T, LBR 깊이 16 |
| 입력 | 실험 1과 같음 + 윈도 안 체인(E10) |
| 지표 | 체크포인트 수(논문에서 성능 비용을 정하는 검사 횟수의 대리값), 탐지 스텝, E10 탐지 여부 |
| 반복 | 실험 1과 같음 |

## (선택) 실험 3

- 판정 비교 방식: T = 11에서 ≥(11주차)와 >(논문 "exceeds")를 비교해 경계 11의 판정이 갈리는 것을 보인다.
- 또는 연속 3개 윈도 누적(논문 Ⅶ-B 확장안) 켬/끔. E7(긴 gadget 끼워 넣기) 결과를 보고 정한다.

## 측정 조건과 결과 파일

- **기록할 조건:** OS(기준 macOS 27.2.1 arm64, 재실행 Windows 10/11·CI ubuntu), Python 3.11.15, capstone 5.0.9, pyelftools 0.33(`uv.lock`), gadget DB의 sha256(`data/gadgets` 헤더), 저장소 커밋, 입력 트레이스 목록과 sha256, 실행 명령
- **실행 명령(14주차 구현 예정):** `uv run python experiments/sweep.py --var T --values 5-17 --repeat 3`
- **결과:** `experiments/results/`에 CSV와 Markdown 표로 커밋하고, 최종 보고서(`docs/final_report.md` 6장)에 인용한다.

## 4. 남은 한계와 원논문과의 차이

- **수정하지 않은 반례:** (심형섭 정리, 다른 사례는 취합 때 더함)
  - **긴 gadget 끼워 넣기(E7-가, 원논문 한계 Ⅶ-B):** gadget 10개마다 명령 7개짜리 조각을 끼우면 연쇄가 10에서 끊겨 gadget 30개짜리 체인도 놓친다. 6개짜리 gadget을 끼우거나 11개 뒤에 끼우면 탐지된다. 보완 방법은 논문의 연속 3개 윈도 누적이다(14주차 선택 실험 3 후보).
  - **gadget 접합(E8-가, 원논문 한계 Ⅸ-B):** 직접 jmp가 든 조각은 gadget이 아니어서 연쇄가 끊긴다. 보완 방법은 논문의 직접 분기 따라가기다.
  - **직접 jmp로 들어온 현재 gadget(E8-나, 명세상 미지원):** 체크포인트 pc가 gadget이어도 간접 분기로 들어온 것이 아니면 과거·미래 어느 쪽에도 세지 않아 연쇄가 1 작게 나온다. 1을 더하는 보완은 고정 사례 판정과 실제 정상 트레이스의 최대 연쇄(1)를 바꾸지 않았지만(저장소 밖 스크립트로 확인), 정의(design.md 1절)를 바꾸는 일이라 적용하지 않았다.
  - **loop 조각을 쓴 체인(E2-나, 원논문 한계 Ⅸ-B):** loop 필터를 고친 뒤에는 `loopne X; ret` 같은 조각이 gadget이 아니어서 연쇄가 거기서 끊긴다(같은 체인이 연쇄 12 → 6). 분기하지 않도록 rcx·플래그를 맞추면 공격에 쓸 수 있으므로 gadget 접합(E8-가)과 같은 갈래의 한계다.
  - **retf로 끝나는 gadget(E3, 명세상 미지원):** far return은 RIP와 함께 CS를 꺼내 코드 세그먼트를 바꿀 수 있어 sd·adv를 null로 둔다(libc 8,685개, ld-linux 845개). 미래 연쇄는 거기서 멈춘다. PR #8 리뷰 4건 중 이 건은 check로 만들지 않았다.
  - **ROPgadget 대조 범위(E4, 명세상 미지원):** ROPgadget은 RIP 상대 메모리 간접 분기로 끝나는 조각(PLT 스텁, `_start`)을 내지 않아, 교차검증은 포함 관계(ROPgadget이 찾은 것은 모두 우리 DB에 있음)로만 확인했다.
  - **과거 연쇄 상한 16(E6, 반례 아님):** 미래 연쇄를 볼 수 없는 체크포인트에서는 연쇄가 16을 넘지 못하므로 T ≥ 17에서는 과거만 남은 체인을 놓친다(논문 권장 T는 11~16, Ⅶ-A).
- **원논문과의 차이:** 12주차 2.5절에서 바뀐 점(jmp gadget 처리 결정 등, 김수영)
